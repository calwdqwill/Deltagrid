## Preview evidence

После PR/review нужно получить один из двух вариантов preview evidence:

1. Merge/cherry-pick в `preview`, дождаться `CI` и `Deploy Preview`, затем запустить preview Funding release report.
2. Если GitHub runner снова упирается в SSH reachability, использовать уже описанный public HTTP fallback только после фактической доставки commit на preview.

Минимальные команды для preview evidence:

```bash
BASE_URL=http://127.0.0.1:8011 FRONTEND_URL=http://127.0.0.1:3012 sh scripts/funding-qa-smoke.sh
BASE_URL=http://127.0.0.1:8011 FRONTEND_URL=http://127.0.0.1:3012 COMPARE_BASE_URL=http://127.0.0.1:8000 sh scripts/funding-release-ci-report.sh
```

Если `COMPARE_BASE_URL` недоступен или funding rows пустые, blocked report остаётся валидным evidence artifact, но не является release-ready approval.

## Production release gate

Не выполнять production deploy и tag из feature branch.

Финальная последовательность:

1. PR review и зелёный CI.
2. Preview evidence приложен к PR или release notes.
3. Merge в `main`.
4. PostgreSQL backup перед deploy.
5. Production deploy.
6. `scripts/release-smoke.sh` на production.
7. Browser QA production для `/version`, `/funding`, `/funding?view=qa`, `/data-health` и ключевых terminal screens.
8. Проверить `/version` и `VERSION=1.5.0` на runtime.
9. Создать annotated tag `v1.5.0`.
