# === СИСТЕМНЫЕ ПРАВИЛА РАБОТЫ: ПРОЕКТ DELTAGRID ===

## КОНТЕКСТ ПРОЕКТА
- DeltaGrid — арбитражный сканер Spot ↔ Perp DEX (CEX-CEX, DEX-CEX, Spot-Perp) + RWA/Treasury Intelligence
- URL разработки: http://127.0.0.1:3000/ (Windows: используй 127.0.0.1, не localhost — избегает IPv6 timeout)
- Стек: Frontend Next.js 14 + React + TypeScript + Tailwind; Backend FastAPI (Python 3.11)
- Данные: CoinGecko API (primary), CoinGlass, GeckoTerminal, alternative.me
- RWA данные: CoinGecko для токенов (XAUT, PAXG, CFG), ручной seed для BUIDL/USDY, ручной seed для Treasury entities
- Cache: In-memory singleton LRU с TTL 300s (Redis-ready interface)
- Persistence: SQLite (PostgreSQL-ready via Alembic), 34 tables total
- Auth: JWT + bcrypt, optional middleware (public routes stay public), dual-token refresh
- Локализация: RU/EN с первого дня, centralized dictionaries, no hardcoded mixed labels
- Дизайн: Light theme, premium institutional, #F8F9FA bg, #FFFFFF cards, #0F172A text
- Фазы: Phase 1 ✅ DONE, Phase 2 ✅ DONE, Phase 3 ✅ DONE, Phase 4 ✅ DONE, Phase 5 ✅ DONE, Phase 6 📋 Planned

- Fallback: если 429/401/нет ключа — mock данные + баннер "Введите API-ключ"

Exchange Connectors (Phase 3):
- Binance: REST spot API, HMAC-SHA256 signing, 1200 req/min
- Bybit: V5 unified API, HMAC-SHA256 signing
- OKX: REST API, HMAC-SHA256 signing, passphrase required
- Hyperliquid: direct REST (allMids, clearinghouse), wallet signing для trading
- API keys encrypted via Fernet AES-256, backend-only, never exposed to frontend

Perp DEX Adapters:
- Hyperliquid: REST tickers (direct API Phase 3), funding rate, open interest
- Aster: REST tickers (direct API Phase 3), funding rate
- Lighter: REST tickers (direct API Phase 3)
- Если источник не даёт поле — верни null + availability meta, не выдумывай число

RWA Domain (Phase 5):
- RWA assets: `is_executable=False` — никогда не попадают в scanner/execution
- Treasury entities: ручной seed, snapshots через `TreasuryService.seed_entities()`
- Tokenization platforms: ручной seed, no external API dependency
- RWA alert types: `rwa_price_threshold`, `treasury_holdings_change` — AlertService поддерживает любой string rule_type
- RWA adapter: `BaseRwaAdapter` ABC в `adapters/rwa/`, `CoinGeckoRwaAdapter` для CG-backed токенов

Статусы данных (явно разделяй):
- live — свежий запрос < TTL
- cached — из кэша, в пределах TTL
- stale — кэш просрочен, но есть данные
- fallback — mock/тестовые данные
- partial — часть полей null
- unavailable — источник молчит

## 4. СПРЕДЫ, СИГНАЛЫ И ФОРМУЛЫ
Формулы:
- grossSpreadPct = ((sellPrice - buyPrice) / buyPrice) * 100
- netProfitPct = grossSpreadPct - feeBuyPct(0.10) - feeSellPct(0.10) - slippagePct
- paperTradePnl = (exitPrice - entryPrice) * quantity - fees
- paperPnlPct = (paperTradePnl / (entryPrice * quantity)) * 100

Сигналы (explicit logic, не хардкод):
- STRONG — netProfitPct > 1.0% + volume OK
- BUY+SELL — netProfitPct 0.5-1.0%
- MARGINAL — netProfitPct 0.1-0.5%
- HOLD — всё остальное

Всегда показывай calculation breakdown в Detail View.

## 6. БЭКЕНД (FastAPI)
- Слои: API → Service → Adapter → DTO/Schema → Domain logic → Persistence
- Обязательные сервисы: CoinGeckoService, PerpDEXService, SpreadCalculator, SignalClassifier, PreferenceService, CacheService, AuthService, PaperTradingService, PerformanceService, ExchangeAccountService, ExecutionService, RiskManager, OrderManager, AlertService, NotificationService, RwaAssetService, TreasuryService
- Адаптеры: CoinGecko, Hyperliquid, Aster, Lighter, Binance, Bybit, OKX, CoinGeckoRwaAdapter (RWA)
- Endpoints:
  - Public: /scanner, /scanner/{id}, /preferences, /health, /status, /auth/register, /auth/login, /billing/plans, /market/*, /rwa/*, /treasury/*
  - Auth-required: /auth/me, /paper/*, /performance/*, /exchange-accounts/*, /execution/*, /risk/*, /alerts/*, /notifications/*
- Cache: singleton InMemoryCacheService с TTL 300s, warm-up при старте. **CacheService is async** — `await cache.get(key)`, `await cache.set(key, value, ttl_seconds)` (NOT keyword `ttl`)
- Auth: JWT HS256, optional middleware (public routes stay public), bcrypt password hashing, dual-token refresh
- Order Intent Flow: ScannerRow → OrderIntentModal → POST /execution/intents → risk check → pending_confirmation → POST /execution/intents/{id}/confirm → OrderManager → exchange (только если is_live=True)
- RWA Flow: RwaAssetService.seed_assets() при старте → CoinGeckoRwaAdapter.fetch_assets() для CG-backed токенов → snapshots с TTL 300s

## 11. ПРОВЕРКА ПОСЛЕ ОПЕРАЦИЙ
После любой операции с API/БД/кэшем:
- Выведи sample (5 записей) или summary
- Для сканера: проверь dataStatus (live/cached/stale/fallback)
- Для спредов: проверь сходимость gross vs net, не отрицательный ли net при positive gross
- Для UI: проверь, что RU/EN labels не смешаны
- Для auth: проверь, что токен сохраняется как string (не object), и Authorization header = Bearer <jwt>
- Для execution: проверь, что API keys encrypted, frontend видит только has_keys
- Для RWA: проверь, что `is_executable=False`, asset не попадает в scanner
- Для Treasury: проверь, что snapshots seeded корректно (btc_holdings ≥ 0, report_date ≤ today)
